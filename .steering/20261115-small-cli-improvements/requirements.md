# 要求内容

## 概要

CLI の小さな使い勝手の改善3件をまとめて入れる。(1) `show` に解禁日を表示、(2) インタラクティブシェルの補完をオプション名と値まで広げる、(3) `daily stats` の達成率にバーを添える。

- **関連Issue**: https://github.com/kanan4gh/dev-tasks2-py/issues/35 , https://github.com/kanan4gh/dev-tasks2-py/issues/36 , https://github.com/kanan4gh/dev-tasks2-py/issues/37
- **使用ハーネス**: Claude Code
- **軽量パス**: 非適用
  - 基準3を満たさないため通常パス(下の「パス判定」を参照)

## パス判定（**通常パス・軽量パスのどちらでも必ず記載する**。基準の正は add-feature 手順のステップ4）

- [x] 1. 既存パターンの踏襲のみで、新しいアーキテクチャ要素・新規依存を導入しない
- [x] 2. 変更対象が3ファイル以下(テスト除く)
- [ ] 3. 対象文書の更新が不要
- [x] 4. データ形式・API契約の破壊的変更がない

**判定理由**:

- 基準1: 満たす。rich の表示と prompt_toolkit の `Completer`(既存依存)の範囲で、新しい層も依存もない
- 基準2: 満たす。`cli/renderer.py`・`cli/shell.py`・`cli/commands/daily.py` の3ファイル(テスト除く)
- 基準3: 満たさない。`docs/functional-design.md` の「解禁日は CLI の詳細パネルには出ない」「`daily stats` の説明」「`shell` の説明」が実装と食い違うようになり、記述そのものを更新する必要がある
- 基準4: 満たす。保存データ・API は変えない。表示と補完の追加のみ

**G3受け入れ**: 不要(アダプタ構成・権限・フックは変更しない)。

## 背景

3件とも、過去の振り返りの「次回への改善提案」から起票された小機能。#35 は `scheduled_date` が `start` の可否を左右するのに `show` から見えない、#36 は補完がコマンド名止まり、#37 は達成率が数値だけで傾向を追いにくい。

## ユースケースの軸

利用者が (1) `show` で着手できる日を確認でき、(2) シェルで `--priority ` の後に候補が出て、(3) `daily stats` で達成率の増減を目で追える。

## 実装対象の機能

### 1. show に解禁日を表示(#35)
- `render_task_detail` に `Sched`(解禁日)の行を足す。値がある場合のみ。`Due` の次の行
- 解禁日が今日より未来のときは、`start` できない旨を併記する(判定は `start` と同じ「今日」の定義)

### 2. シェル補完の拡張(#36)
- コマンド → サブコマンド → オプション名 → 列挙値の順に補完する。`prompt_toolkit` の `Completer` を自作する(`NestedCompleter` は値のあとに他のオプションを補完できないため)
- 候補は typer のコマンド定義(`typer.main.get_command(app)`)から作るので、コマンドやオプションの増減に手作業で追随しなくてよい
- 実行時に変わる候補(プロジェクト名など)は対象外

### 3. daily stats のバー(#37)
- 達成率の列に、固定幅10の文字バー(`█` と `░`)と数値を並べる
- 記録が無い日(`rate is None`)は、バーを出さず従来どおり `--`

## 受け入れ条件

### show
- [ ] 解禁日があるタスクの `show` に解禁日が出る。無ければ行が出ない
- [ ] 解禁日が未来のとき、着手できない旨が出る。過去・今日のときは出ない

### シェル補完
- [ ] `lis` → `list`、`project cr` → `project create` が補完される(従来の挙動の維持)
- [ ] `list --` でそのコマンドのオプション(`--all` 等)が補完される
- [ ] `add x --priority ` で `high` / `medium` / `low` が補完され、`--priority high ` のあとにも他のオプションが補完される
- [ ] 実在しないコマンドの後では補完候補を出さない(例外を投げない)

### daily stats
- [ ] 達成率 100% で満タン、0% で空、50% で半分のバーが出る
- [ ] 記録が無い日は `--` のまま

## 成功指標

- 既存テストの全通過に加え、3件分のテストが足される

## スコープ外

- プロジェクト名・タスク ID などの実行時の候補の補完
- `daily list` の表示変更、`list` 一覧への解禁日列の追加
