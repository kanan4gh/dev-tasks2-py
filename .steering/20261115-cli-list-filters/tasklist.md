### 計画と実績の差分

**計画と異なった点**:

- 期限切れの色を、計画の「赤」から「太字の赤」に変えた。優先度 `high` も赤(`_PRIORITY_STYLES`)で、Priority 列と Due 列が隣り合うため、`high` で期限が先のタスクと、期限切れのタスクが見分けられないとコードレビューで指摘された。PRD の「赤色でハイライト」は満たしたまま、太字で区別する
- functional-design の「未実装の設計」節に、一覧表示の追加列(Priority・Due・期限の色分け)の古い案が残っていた。Priority と Due は実装済みになったので、節を「Branch 列だけを足す案」に縮め、期限の「今日以前は赤」(実装は「今日より前」)の食い違いも直した。#57 で「未実装の節に隔離した」ものが、実装が進むと陳腐化する例
- `SortKey`(CLI の選択肢)と `TaskFilter.sort`(サービスが受ける値)の二重定義を、食い違いを検査するテストで守った

### 学んだこと

**技術的な学び**:

- `TaskFilter` が既に status / priority / sort を持ち、Web の一覧 API が使っていたので、CLI への露出は小さな作業だった。入口(CLI・MCP・Web)で機能の揃いに差が出るのは、サービス層が持っていても、入口が渡さないため
- 色の意味は、隣の列との組み合わせで決まる。優先度の赤と期限切れの赤を同じ色にすると、赤の意味が曖昧になる
- 壁打ちで先に決めておくと、実装中に判断で迷わなかった。「要求を変える」決定は、PRD に決定日と理由を書いて残した

**プロセス上の改善点**:

- 「実装するか、要求を変えるか」を、項目ごとに推奨と理由を添えて聞くと、一括で決まり、往復が少なかった

### 次回への改善提案

- Web GUI に、期限切れの強調がない(PRD に未実装と明記した)。CLI と同じ判定(`open` / `in_progress` で期限が今日より前)にそろえる小さな作業にできる
- MCP の `list_tasks` は status しか受けず、priority と sort を受けない。入口の揃いを整える作業にできる
- 日本語のタイトルは2バイト幅で、40文字に切り詰めても、80桁の端末では Title 列が折り返される。切り詰め幅を、表示幅(セル数)で決める見直しができる
- 概況表示の中身が入口で揃っていない件(#72 の振り返り)とあわせて、「入口の揃い」の棚卸しにできる
