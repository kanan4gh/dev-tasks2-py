# 要求内容

## 概要

TypeScript 版の記述が残る開発ガイドラインと、実際の構成から乖離したリポジトリ構造定義書を、現在の Python 3.12 / uv / 複数ハーネス対応の実態へ更新する。変動しやすい件数や重複した手順を減らし、今後も正典と実装の対応を追跡しやすい文書にする。

- **関連Issue**:
  - https://github.com/kanan4gh/dev-tasks2-py/issues/28
  - https://github.com/kanan4gh/dev-tasks2-py/issues/40
- **使用ハーネス**: Codex
- **軽量パス**: 非適用

## パス判定

- [x] 1. 既存パターンの踏襲のみで、新しいアーキテクチャ要素・新規依存を導入しない
- [x] 2. 変更対象が3ファイル以下（テスト除く）
- [ ] 3. 対象文書（`AGENTS.md` とハーネスアダプタの規範記述・AGENTS.md プロダクト固有層が列挙する永続ドキュメント・`docs/procedures/` の手順書とテンプレート）の更新が不要
- [x] 4. データ形式・API契約の破壊的変更がない

**判定理由**:

- 基準1: **満たす**。既存のコード・設定・手順を文書へ正しく反映する作業であり、新しいレイヤー、抽象化、ライブラリは導入しない。
- 基準2: **満たす**。成果物の変更対象は `docs/development-guidelines.md` と `docs/repository-structure.md` の2ファイル。`.steering/` は作業記録であり成果物ファイル数には含めない。
- 基準3: **満たさない**。AGENTS.md が列挙する永続ドキュメント2件の記述そのものが変更の実体である。外部の実装変更を一覧へ転記するだけの記録例外には該当しない。
- 基準4: **満たす**。実行可能コード、YAMLデータ形式、CLI・MCPの公開契約は変更しない。

4項目すべてを満たさないため、**通常パス**を適用する。

## G3実機受け入れ判定

- **不要**。ハーネスのアダプタ構成・定義メタデータ・権限・フック・設定を変更せず、永続ドキュメントだけを更新するため。

## 背景

`docs/development-guidelines.md` は TypeScript 版から移行されておらず、Node.js、npm、TypeScript、Vitest、Husky、必須 GitHub Actions、`develop` ブランチなど、現リポジトリに存在しない前提を案内している。この文書に従うと、存在しないコマンドやファイルを使うことになる。

`docs/repository-structure.md` は実装済みコマンドを未実装と記載し、`src/task_mcp/`、多数の `task_cli` モジュール、テスト分類、SDDハーネス関連のトップレベル要素を欠いている。また、テスト件数を固定値で記載しているため、機能追加のたびに陳腐化する構造になっている。

両文書は add-feature の軽量パス基準3を判断する対象であり、新規参加者や別ハーネスのエージェントが開発方法と配置規則を理解する入口でもある。実態との乖離は、誤った作業手順と誤ったパス判定につながる。

## ユースケースの軸

**開発者またはAIコーディングエージェントが、現在のリポジトリ構成・開発手順・品質ゲートを文書だけから正しく把握し、存在するコマンドと配置規則に従って変更を進められる。**

## 実装対象

### 1. 開発ガイドラインの Python / uv 化

- 必須環境を Python 3.12、uv、Git とし、devcontainer は任意の選択肢として説明する
- セットアップ、日常開発、個別検証、単一ローカル品質ゲートのコマンドを現行構成へ合わせる
- 命名、型、フォーマット、関数設計、エラー処理、コメントの例を Python へ置き換える
- pytest、ruff、basedpyright と、一時ディレクトリを使うテスト方針を記載する
- `main` 起点のフィーチャーブランチ、Conventional Commits、PR、`pyproject.toml`、GitHub Release を使う現行フローへ合わせる
- GitHub Actions は任意の手動ミラー、ローカル品質ゲートは必須の正として区別する
- SDD、steering状態、対話型実機受け入れ、外部有料自動化禁止の詳細は各正典へリンクし、重複定義を避ける

### 2. リポジトリ構造定義書の実態同期

- 構造図へ `src/task_mcp/`、現在の `task_cli` モジュール、主要なトップレベル文書・スクリプト・ハーネスアダプタを反映する
- 実装済みコマンドの「未実装」表記を除去する
- CLI と MCP を2つの入口として示し、共有する usecase / service / storage / model とパッケージ直下の共有基盤モジュールの依存方向を説明する
- `tests/` は固定件数や全ファイル列挙ではなく、ルート直下と分類ディレクトリの役割で説明する
- ファイル配置規則へ MCP、共有基盤モジュール、テスト分類を反映する
- 設定・規範ファイルの表へ `AGENTS.md`、各ハーネスアダプタ、品質ゲート関連設定を反映する

### 3. 陳腐化しにくい記述への整理

- テスト件数、ツールの開発環境上のパッチバージョンなど、頻繁に変わる数値を正典として固定しない
- コマンドや設定の詳細が別の正典にある場合は役割と参照先を示し、同一ルールの重複記載を抑える
- 文書内の例はリポジトリに実在するパス、クラス、コマンドだけを使用する
