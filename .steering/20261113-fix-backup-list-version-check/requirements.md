# 要求内容

## 概要

バグ Issue 3件(#32 バックアップの前世代削除 / #33 `project list` の桁揃え崩れ / #34 `--version` の更新判定)を1つの作業でまとめて修正する。

- **関連Issue**:
  - https://github.com/kanan4gh/dev-tasks2-py/issues/32
  - https://github.com/kanan4gh/dev-tasks2-py/issues/33
  - https://github.com/kanan4gh/dev-tasks2-py/issues/34
- **使用ハーネス**: Claude Code
- **軽量パス**: 非適用
  - 基準1(新規依存・新モジュール)と基準2(変更対象6ファイル)を満たさないため、通常パスとする

## パス判定

- [ ] 1. 既存パターンの踏襲のみで、新しいアーキテクチャ要素・新規依存を導入しない
- [ ] 2. 変更対象が3ファイル以下(テスト除く)
- [x] 3. 対象文書(`AGENTS.md` とハーネスアダプタの規範記述・AGENTS.md プロダクト固有層が列挙する永続ドキュメント・`docs/procedures/` の手順書とテンプレート)の更新が不要
- [x] 4. データ形式・API契約の破壊的変更がない

**判定理由**:

- 基準1: 満たさない。`packaging` を `pyproject.toml` の依存へ明示宣言する(環境には transitive で入っているが、直接 import する以上は明示する。starlette 等と同じ扱い)。バックアップ処理の共有モジュール `task_cli/backup.py` も新設する
- 基準2: 満たさない。`backup.py`(新規)/ `reset.py` / `migrate.py` / `project.py` / `main.py` / `pyproject.toml` の6ファイル
- 基準3: 満たす。`docs/` の永続ドキュメントにバックアップ・project list の表示仕様の記述はなく(grep 済み)、方針変更も伴わない。更新が必要と判明した場合はステップ7で扱う
- 基準4: 満たす。データ形式・API契約は変えない。バックアップの退避先名のみ変わるが、退避先は復旧用の副産物でありデータ形式ではない(旧 `~/.task-py.backup` は読まず・消さず残す)

## 背景

いずれも過去の振り返りで「改善提案」として記録されていたが、実態は次のバグである。

- #32: `reset` / `migrate` がバックアップを取る前に前回のバックアップを `rmtree` する。`reset` を2回続けると1回目の退避データが失われ、`migrate` 後の `reset` でも移行前データが失われる
- #33: `project list` が名前を20桁固定で整形するため、21文字以上の名前で後続カラムがずれる
- #34: `--version` が `latest != current` で判定するため、ローカルがリリースより新しい開発版でも「新しいバージョンが利用可能」と表示される。案内に従うと開発版がリリース版で置き換わる

## ユースケースの軸

> 利用者が `reset` / `migrate` を何度実行しても過去のバックアップが黙って失われず、`project list` が名前の長さに関わらず整列して表示され、`--version` がリリースより新しいときに誤って更新を促さない。

## 実装対象の機能

### 1. バックアップの世代管理(#32)
- 退避先を `~/.task-py.backup.<YYYYMMDD-HHMMSS>` の世代別ディレクトリにする
- 新しい世代の退避に成功した後でだけ、保持数(5世代)を超えた最古の世代を削除する
- 確認ダイアログに退避先の形式と保持世代数を明示する
- `reset` と `migrate` は共有ヘルパー `task_cli/backup.py` を使う。退避先は共有のままとする(どちらの退避も同じ世代列に並ぶ。分けると「直近の退避」を探す場所が増えるため)
- 旧形式の `~/.task-py.backup` は触らない(読まない・消さない・世代に数えない)

### 2. `project list` の Table 化(#33)
- rich の `Table`(`box=None, padding=(0, 1)`)に置き換える。列幅は名前の長さに応じて自動調整される
- アクティブプロジェクトの `*` マーカーと緑ハイライトは維持する
- Inbox 行も同じ Table に載せ、桁揃えの根拠を1箇所に集約する

### 3. `--version` の比較(#34)
- `packaging.version.Version` で `latest > current` のときだけ案内を表示する
- どちらかが解釈できない場合は比較せず何も表示しない

## 受け入れ条件

### バックアップの世代管理
- [ ] `reset` を2回続けて実行しても、1回目の退避が残っている
- [ ] `migrate`(既存データあり)のあとに `reset` しても、migrate 前の退避が残っている
- [ ] 保持数(5)を超えたとき、最古の世代だけが消える
- [ ] 退避(copytree)が失敗したとき、既存の世代は1つも削除されない
- [ ] 同一秒に2回実行しても、世代同士が上書きされない
- [ ] 旧 `~/.task-py.backup` が残っていても触られない
- [ ] 確認ダイアログに退避先の形式と保持世代数が表示される

### `project list`
- [ ] 21文字以上のプロジェクト名でも、タスク数のカラムが全行で同じ位置に揃う(名前が省略されない)
- [ ] アクティブプロジェクトに `*` が付く
- [ ] Inbox 行が表示され、件数が正しい

### `--version`
- [ ] latest > current のとき更新案内が出る
- [ ] latest == current のとき案内が出ない
- [ ] latest < current(開発版)のとき案内が出ない
- [ ] 解釈できないタグ・取得失敗のとき案内が出ない

- 3件の Issue が Close できる

## スコープ外

以下はこのフェーズでは実装しません:

- バックアップから復元するコマンド(`restore`)の追加
- 世代数を設定可能にすること
- project list 以外のコマンドの Table 化
- バージョン更新判定の結果のキャッシュ
