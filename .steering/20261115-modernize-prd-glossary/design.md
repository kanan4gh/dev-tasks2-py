# 設計書

## 方針

実装を正として、節ごとに実コードまたは現行化済みの `functional-design.md` と照合して書く。用語の機械的な置き換えにしない(#43 で、ID 採番など TypeScript 版由来以外の誤りも見つかった)。要求の内容は変えず、表記と実装状況の注記だけを直す。

## product-requirements.md

- **未実装の扱い**: 機能9・10・11(Git ブランチ連携・完了時 PR・GitHub Issues 同期)の見出しに【未実装】を付け、直後に「実装状況: Python 版には未実装。設計は `functional-design.md` の『未実装の設計』節」と書く。受け入れ条件は残す。CLI インターフェースのコードブロックは「実装済み」と「未実装（要求のみ）」の2つに分ける。ワークフロー(v1.1 以降)・GTD の対応・非機能要件(Git 操作失敗時の復帰・Token の保存)・リリース計画の v1.1 の行は、未実装の部分に印を付ける
- **実装との差の注記**: 実装済みの機能のうち CLI に無い要求(`list --status` / `--priority` / `--sort`、期限切れの赤色表示、`list` の ブランチ・作成日の列)は、該当の受け入れ条件に「（CLI 未実装。Web の一覧 API にはある）」のように注記する
- **チェックボックス**: 受け入れ条件のチェックは要求の定義であり、実装の進捗を表さない。機能要件の冒頭にその旨を書く(個別に付け替えない)
- **データモデル・保存形式**: `src/task_cli/models/task.py` の実フィールド(snake_case)と YAML のサンプルにする。ID 採番は「最大 ID + 1」(最大のタスクを削除すると再利用される)
- **配布・環境**: npm・Node.js を、`uv tool install` と Python 3.12 に。KPI の「npm 月間ダウンロード数」は Python 版では計測できないので、行は残して計測不能と注記する(目標値は変えない。代わりの指標の決定は別途)

## glossary.md

- パス・クラス名: `src/task_cli/` 配下の実在するものへ。`IStorage` は実コードに無ければ、実在する構造(ストレージクラスの共通の形)の説明に直すか削除する
- 技術用語: Commander.js → typer、Vitest → pytest、inquirer → `typer.confirm`、husky・lint-staged → 実在しないので削除、simple-git → Git 連携が未実装なので削除(用語集に載せるのは実在する技術)
- Git・GitHub 連携の用語: 残し、「未実装（要求のみ）」と明記。`実装:` の行は設計書の節への参照に
- 索引と更新日を直す

## 検査テスト

`tests/procedures/test_functional_design_currency.py` と同じ流儀。対象2文書をパラメータ化して、(1) 旧い語・パス・ファイル名、(2) `task <cmd>` 形式、(3) `src/`・`tests/` のパスの実在、(4) `task-py <コマンド>` の実在(【未実装】を見出しに持つ節と、その見出しを持つコードブロックの節を除く)を検査する。

## テスト戦略

変更前の文書で検査テストが失敗することを確認してから、文書を直す。期待を緩めて通さない。
