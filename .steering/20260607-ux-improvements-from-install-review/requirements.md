# 要求内容

## 概要

インストールフローを実際に試した際に発見したUX上の問題点を改善する。

## 背景

ユーザーが GitHub リリースからのインストールを実施した際に、以下の問題が発見された。初めて使うユーザーにとって不便・不安な点を解消し、ツールの使いやすさを向上させる。

## 関連 Issue

https://github.com/kanan4gh/dev-tasks2-py/issues/15

## 実装対象の機能

### 1. `--version` オプション
- `task-py --version` または `task-py -V` でバージョンを表示する
- 表示時に GitHub の latest リリースを確認し、新しいバージョンがあればアップデートコマンドを案内する
- ネットワークエラー時はバージョン表示のみ行い、チェックは静かにスキップする

### 2. `migrate` コマンドの安全性向上
- 既存の Python 版データを上書きする前に、バックアップを `~/.task-py.backup/` へ自動作成する
- 上書き確認プロンプトをより明確にする（「既存の task-py データが失われます」と明示）

### 3. アンインストールガイドを README に追記
- ツール本体の削除コマンド（`uv tool uninstall dev-tasks2-py`）
- データの削除コマンド（`rm -rf ~/.task-py/`）
- 「開発者向け」セクションの前に独立したセクションとして追加

### 4. `reset` コマンドの実装
- `task-py reset` で `~/.task-py/` 以下のデータをすべて削除する
- 実行前に確認プロンプトを表示し、誤操作を防ぐ
- 削除前にバックアップを `~/.task-py.backup/` へ自動作成する

## 受け入れ条件

### `--version` オプション
- [ ] `task-py --version` でバージョン番号が表示される
- [ ] `task-py -V` でも同様に動作する
- [ ] 新しいバージョンがある場合、アップデートコマンドが案内される
- [ ] ネットワーク接続がない環境でもクラッシュせずバージョンのみ表示される

### `migrate` コマンドの安全性向上
- [ ] `migrate` 実行時、既存データがある場合はバックアップが `~/.task-py.backup/` に作成される
- [ ] 確認プロンプトに「既存の task-py データが失われます」の旨が明示される

### アンインストールガイド
- [ ] README にアンインストールセクションが追加されている
- [ ] ツール本体とデータの両方の削除手順が記載されている

### `reset` コマンド
- [ ] `task-py reset` で確認プロンプトが表示される
- [ ] 確認後、`~/.task-py/` 以下のデータが削除される
- [ ] 削除前に `~/.task-py.backup/` へバックアップが作成される
- [ ] キャンセル時はデータが保持される

## スコープ外

以下はこのフェーズでは実装しません:
- `migrate` のマージ機能（TypeScript版と Python版データのマージ）
- アップデート自動適用機能
- バックアップの世代管理
