# 要求内容

## 概要

Web GUI に project 管理(作成・アクティブ切替・改名・削除)を足す(GUI 構築ロードマップの作業単位 D1)。あわせて、プロジェクト名の検証を service 層に入れる。名前が `~/.task-py/projects/{name}/` のパスにそのまま使われており、`../x` のような名前を作れてしまうため、Web から作れるようにする前に塞ぐ。

- **関連Issue**: https://github.com/kanan4gh/dev-tasks2-py/issues/75
- **使用ハーネス**: Claude Code
- **軽量パス**: 非適用
  - 基準2・3を満たさないため通常パス(下の「パス判定」を参照)

## 背景

作業単位 D(周辺)は3つに分ける(D1 project 管理 → D2 daily/routine → D3 タイマー)。現在の GUI は project を読むだけで、作成・切替・改名・削除は CLI でしかできない。

調査で見つけた穴: `ProjectService.create_project` / `rename_project` は名前を検証しない。`resolve_storage_path` は `Path(f"~/.task-py/projects/{name}/tasks.yaml")` と文字列結合する。GUI は localhost 限定・CSRF 検査つきだが、書き込み口を増やす以上、名前の検証は同じ変更で入れる。

## ユースケースの軸

利用者が GUI だけで、プロジェクトを作り、CLI/MCP が既定で対象にするプロジェクトを切り替え、名前を直し、不要になったものを登録から外せる。

## 実装対象の機能

### 1. プロジェクト名の検証(service 層。CLI・MCP・Web に効く)
- 作成・改名の新しい名前に適用する。空・前後の空白・制御文字・`/` `\`・`.` `..`・先頭が `.` を拒否する。長さは64文字まで
- 違反は新しい例外 `InvalidProjectName(AppError)`(原因と対処つき)。Web では 400
- 登録済みの名前は検証しない(読み込めなくならないように)。`inbox` という名前は従来どおり許す(パスが分かれているため)

### 2. Web API
- `POST /api/projects` 本文 `{"name": ...}` → 201。**作成するとアクティブになる**(CLI の `project create` と同じ。サービスの挙動は変えない)
- `POST /api/projects/{name}/use` → 200(アクティブ切替)
- `POST /api/projects/{name}/rename` 本文 `{"new": ...}` → 200
- `DELETE /api/projects/{name}` → 200。登録を外すだけでデータのディレクトリは残す(CLI の `project remove` と同じ)
- いずれも CSRF 検査を通す。存在しない名前は 404、同名は 409、不正な名前は 400

### 3. 画面
- サイドバーに「＋ プロジェクト」(名前入力ダイアログ)
- プロジェクトの見出しに「アクティブにする」(すでにアクティブなら非表示)・「名前を変更」・「削除」
- 削除は確認ダイアログ。「データは削除されません」と表示する
- 改名後は新しい名前の画面に移る。削除後は「すべて」画面に移る。「アクティブ」は CLI/MCP の既定の対象であることをラベルで示す

## 受け入れ条件

- [ ] `../x`・`a/b`・`.hidden`・空文字・65文字の名前は、作成も改名も拒否される(CLI・Web とも)。登録済みの旧名のプロジェクトは読める
- [ ] Web から作成・切替・改名・削除ができ、`config.yaml` に反映される
- [ ] 作成は201でアクティブになる。同名は409。存在しない名前の use/rename/delete は404
- [ ] CSRF 検査(JSON必須・Origin・Sec-Fetch-Site)が4つの書き込みに効く
- [ ] 改名でタスクのデータが新しい名前のディレクトリへ移り、画面が追随する
- [ ] 削除後にデータのディレクトリが残り、一覧から消える

## 成功指標

- 既存テストの全通過に加え、検証・API・画面の振る舞いのテストが足される

## スコープ外

- 削除時のデータディレクトリの削除・アーカイブ(`project remove` と同じく残す)
- プロジェクトの完了状態(#25)
- 一括操作・undo(ロードマップの決定どおり入れない)
