## タスク管理の原則

- `active`: 作業系列が継続中。未完了を許容する
- `paused`: 意図的な中断。有効な中断記録がある場合に未完了を許容する
- `complete`: 全タスクと振り返りが完了。未完了を許容しない
- 完了・技術的スキップは実態に合わせて即時記録する
- 「今日はここまで」はスキップではなく`scripts/steering_state.py pause`で記録する
- 最終品質ゲート、コミット、G3受け入れ記録、push、PRはチェックボックスにしない

### 計画と実績の差分

**計画と異なった点**:

- 計画になかった「タイマー実行中の改名・削除を断る」を入れた。タイマーは開始時の project 名を持つので、名前が消えると `time stop` が記録先を失う。段2で実際に動かして挙動を確かめ、Web では409で断ることにした(CLI・MCP の穴は #76)
- `ErrorBox` の競合表示を「`current` がある409のみ」に絞った。project の409(同名・タイマー)が「別の場所で変更されました」の箱に出るのを避けるため。その副作用(行操作の `current` の無い409で閉じるボタンが無くなる)は段3で見つかり、通常の箱に `onClose` を足して直した
- service の「同名」「見つからない」が素の `AppError` だったので、Web で 500 になる。`StateConflictError` / `NotFoundError` に変えた(CLI・MCP は `AppError` を捕まえるので表示不変)

**新たに必要になったタスク**:

- なし(上の変更は既存タスクの内側で処理した)

**技術的理由でスキップしたタスク**:

- 該当なし

### 学んだこと

**技術的な学び**:

- プロジェクト名がパスに直結するのに検証が無かった。書き込み口を増やす作業の前に「入力がどこへ流れるか」を調べたので、実装前に見つかった
- 「確認してから実行」を別々の区間でやると、確認が無意味になる。タスクの `guarded()` で一度直したのと同じ形(#50)を、タイマーでも繰り返しかけた。段3で指摘されて timer_guard の内側に入れた
- 共通の表示部品(`ErrorBox`)の条件を変えると、別の画面の経路に副作用が出る。段2の手操作は project の経路しか見ないので、段3の差分レビューが拾った

**プロセス上の改善点**:

- 段4の implementation-validator は、設計との乖離を「未記録」として拾う。実装の中で決めたことは、その場で design.md に1行足しておくと指摘が減る
