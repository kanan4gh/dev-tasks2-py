## タスク管理の原則

- `active`: 作業系列が継続中。未完了を許容する
- `paused`: 意図的な中断。有効な中断記録がある場合に未完了を許容する

- 完了・技術的スキップは実態に合わせて即時記録する
- 「今日はここまで」はスキップではなく`scripts/steering_state.py pause`で記録する

**計画と異なった点**:

- Claude Desktop内のCodeセッションでは `~/.claude.json` の登録を使っていたため、インストール更新後にUIから明示的な再接続を行った。コマンドは当初確認したDesktop設定と同じ `task-mcp` で、コード・設定変更は不要だった。
- `uv.lock` は既存の互換版 `mcp 1.27.2` を維持した一方、ロックを使わない隔離インストールでは `mcp 1.30.0` が解決された。両方で1.x制約を満たし、実挙動も成功した。

**新たに必要になったタスク**:

- なし。

**技術的理由でスキップしたタスク**:

- 段4の独立スペック準拠検証を軽量パスの縮約規則によりスキップした。段1の機械検証、段2のstdio・Claude Desktop実機検証、段3の差分セルフレビューで代替した。

### 学んだこと

**技術的な学び**:

- リポジトリの `uv.lock` が互換版を保持していても、`uv tool install` は配布メタデータから依存を再解決するため、上限のないメジャー依存は利用者環境だけを壊し得る。
- MCP SDK 1.xの最新解決版でもstdio初期化と28ツール取得が成功し、`<2` が現行実装の互換境界として機能することを確認できた。

**プロセス上の改善点**:

- MCP接続エラーでは登録設定を先に書き換えず、Claude Desktopのサーバーログと実行ファイルの依存バージョンを突き合わせると、設定・PATH・アプリケーション依存のどこで失敗しているかを短時間で切り分けられる。

### 次回への改善提案

- MCP SDK 2.xへの移行はAPI変更範囲を調査したうえで別Issueに分離し、1.x保守修正と混在させない。
