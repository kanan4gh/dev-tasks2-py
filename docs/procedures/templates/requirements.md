## パス判定（**通常パス・軽量パスのどちらでも必ず記載する**。基準の正は add-feature 手順のステップ4）

- [ ] 1. 既存パターンの踏襲のみで、新しいアーキテクチャ要素・新規依存を導入しない
- [ ] 2. 変更対象が3ファイル以下(テスト除く)
- [ ] 3. 対象文書(`AGENTS.md` とハーネスアダプタの規範記述・AGENTS.md プロダクト固有層が列挙する永続ドキュメント・`docs/procedures/` の手順書とテンプレート)の更新が不要
  - **記録例外**: 変更の実体が対象文書の外にあり、かつ文書の更新がその文書の定める一覧・台帳の項目の追加・削除・値の更新と理由の記述にとどまる場合は本基準を満たす。適用した場合は下の判定理由に「変更の実体はどこか」「どの文書のどの一覧へ何をしたか」を書く
  - 文書への記述そのものが変更の実体である場合(機能一覧への機能追加等)、分類体系・適用範囲が変わる場合、方針・条件・手順そのものを変える場合は満たさない
- [ ] 4. データ形式・API契約の破壊的変更がない

**判定理由**（満たさない項目はその理由、記録例外を使った項目はその内容を書く）:

- 基準1: {満たす / 満たさない: 理由}
- 基準2: {満たす / 満たさない: 変更対象ファイル数と内訳}
- 基準3: {満たす / 満たさない: 理由。記録例外を使った場合はその内容}
- 基準4: {満たす / 満たさない: 理由}

4項目すべてにチェックが付く場合のみ「適用」と宣言できる。この判定結果は add-feature 手順ステップ4.5で、**選択したパスにかかわらず**計画と一緒にユーザーへ提示する。
